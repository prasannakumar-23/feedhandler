What was verified

  • Same book at the endwith random loss up to 40%, duplicates and reordering, across 300 seeds: every message delivered exactly once, in order, and the final book matches the sender's
  • 1,440 checkspass, also under ThreadSanitizer and ASan + UBSan
  • 7 of 7 injected bugs caughtone of them (a relaxed instead of release store in the ring buffer) only by ThreadSanitizer, because x86 hides it
  • Over real UDP socketsa 100,000-packet run with 2% loss, 1% duplicates and 1% reordering rebuilt an identical book

Measured on a shared 2-vCPU Linux sandbox, so indicative only: the ring buffer moved 9M items at about 27M items/s with order preserved, and hand-off latency from push to apply had a median under 1 µs. Tail latencies there were dominated by the virtual machine's scheduler, so no tail figure is claimed.
